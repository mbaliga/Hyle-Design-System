`LICENSE`). Apache-2.0 §6 is explicit that the code license does not grant any trademark rights —
this file states this project's trademark policy separately.

## What's covered

- **"Hyle"** (`rootProject.name = "Hyle"`, Maven coordinate `dev.aarso:hyle`) and **"Aarso"**
  (the `dev.aarso` namespace this coordinate lives under) are Madhav Baliga's marks.
- The **Hyle typeface family names** (Hyle Grotesk Classic, Hyle Print, Hyle Deco Pro, Hyle
  Grotesk Plus, Hyle Classic) as names, independent of the OFL-licensed font files themselves
  (which each carry their own `LICENSE-NOTE.txt` — see `NOTICE`). OFL explicitly permits font-file
  reuse/modification while reserving the *name* — renamed derivatives are fine and expected under
  OFL; using the original family name for a modified font is not.
- Any Hyle logo/wordmark/icon assets, once added to this repo, under a separate all-rights-reserved
  (or CC-BY-ND, once chosen) notice placed alongside those files — never the Apache-2.0 code
  license. No such asset files exist in this repo as of this writing.

## What you may do

- Use `dev.aarso:hyle` as a dependency, fork the code, modify it — Apache-2.0 already grants this.
- Modify and redistribute the OFL fonts under their own OFL terms, **with a different family
  name** for your modified version (standard OFL practice — the Reserved Font Name mechanism).
- Refer to this project by name in truthful, non-confusing statements with a no-affiliation
  disclaimer where relevant.

## What you may not do

- Publish a modified build of this design system under the "Hyle" name, or a modified font under
  its original Hyle family name, in a way that could confuse consumers about origin.
- Use the `dev.aarso:hyle` Maven coordinate for a different, unrelated artifact.
- Use a Hyle logo/wordmark, once one exists, as your own product's branding without permission.

## Enforcement posture

Informal first — a polite rename/re-brand request. Escalates to a repo-host trademark complaint
only if that doesn't resolve it.
